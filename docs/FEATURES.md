## Known gaps and oddities

- No admin/user-management UI; only API routes exist (`/api/users`).
- No client-side tests; no CI configuration (`.github/` does not exist).
- `client/src/pages/LaterPage.tsx` is no longer routed (the vault was its last user). Safe to delete if confirmed unused.
- `client/etc/` and `server/etc/` are empty directories.
- Rate limits are per process unless `REDIS_URL` is set.
- Locked entries: only journal entries and writings (not ideas/notes). Opening them needs a connection (the server checks the PIN); offline they stay locked. A locked entry's text isn't searchable and isn't counted in the profile's written-word totals, and editing it records no actions (actions recorded for it before it was encrypted stay); its title is searchable. Time spent on it counts in the Journal or Writing section like any other entry. Images embedded in its text are files in Documents and are not encrypted. Quick Capture to a day whose entry is locked starts a new entry for that day. Deleted readable copies may still exist in Firestore backups or point-in-time recovery, if those are enabled on the project, until they expire. Tested against the in-memory fakes, not live Firestore.
- Installed app: the colour of Android's gesture-navigation bar can't be set by a web app (Chrome draws it itself, usually transparent over the page or tinted from `theme-color`); `theme-color` applies to both system bars, so it isn't changed for dialogs. The manifest's `theme_color`/`background_color` (splash screen) are dark only; a manifest can't follow the light theme. Pull to refresh, update timing and the cache were tested in headless Chromium with a Pixel 7 profile, not on a real device.
- Vault passphrase loss is unrecoverable by design.
- Profile: no active time exists from before the feature shipped (none was recorded); time per section, visits and action counts exist only from the release of usage tracking (2026-10), and the page says so instead of showing zeros. Actions are counted where they succeed on the server; deleting items isn't counted, and pinning/archiving isn't an edit. Two windows visible at once give shared time to whichever reported first. The current tab's last minute isn't on the page until it is sent. No profile picture. Text copied by an explicit action (quote → note, money idea → project) is counted in both places, as both are separate editable texts. A screen that is locked but still "visible" to the browser keeps counting until the device sleeps. Not verified against live Firestore: aggregation `sum()` and the backfill's BulkWriter preconditions run only against fakes in tests.
- Documents: no Trash; deletes are final (a non-empty folder asks whether to keep its contents). No bulk download or folder download (zip). Folders can't be starred. Uploads show per-file status but no byte-level progress (`apiFetch` uses `fetch`). Drag-to-move is desktop only; on touch use Move. "Move contents up" handles up to 2,000 files directly in one folder.
